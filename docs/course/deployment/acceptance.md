# 完整验收与课程项目交付

开发完成需要一组可复查的结果：相同硬件、相同版本、相同步骤，能够重新运行画面和键鼠。文档、示例和方案交付应围绕同一份版本记录组织。

## 按实际能力验收

| 项目 | 操作 | 通过条件 |
| --- | --- | --- |
| 冷启动 | 完整断电后按正常方式上电 | 无需人工补命令进入运行状态 |
| 网页访问 | 新浏览器会话访问设备 | 菜单和资源完整 |
| 视频 | 固定 1080p 输入，持续改变源画面 | 画面持续更新，格式与输入一致 |
| 键盘 | 空白编辑器输入、释放、修饰键 | 无卡键和重复输入异常 |
| 鼠标 | 四角、中心、拖动与释放 | 坐标正确，按钮能释放 |
| 终端 | 打开、执行只读命令、关闭 | 终端可用，关闭后视频尺寸恢复 |
| 界面缩放 | 调整窗口、进入和退出全屏 | 视频比例与绝对鼠标映射正确 |
| 会话启停 | 多次进入和离开页面 | 采集资源能够回收与重建 |
| USB 重连 | 按当前已支持流程恢复 | 重新枚举后输入正常 |
| 长时间运行 | 记录约定时长与场景 | 无崩溃、持续内存增长或无法恢复停顿 |

当前功能范围为**视频、键鼠、终端和基础设置**。HDMI 热插拔与动态分辨率另行验收；音频、虚拟介质、VPN、OTA 等不属于当前配套功能。

## 三类文件一起交付

```text
release/
├─ manifest.txt       硬件、模块固件、源码和构建版本
├─ SHA256SUMS         实际交付文件的校验值
├─ images/            成套镜像与恢复说明
├─ applications/      匹配的服务、视频应用和依赖说明
├─ patches/           相对指定 SDK 的必要修改
└─ validation/        测试条件、日志、图像和验收结果
```

这是建议的交付目录结构，不表示当前已经生成这些发布文件。文件名与支持范围应与实际打包结果一致。

## 教程实验与整机结果对应

| 教程产物 | 支撑的系统能力 |
| --- | --- |
| 接线表、DTS 与驱动核对 | 板级适配可追踪 |
| NV12 原始帧与连续采集日志 | 视频输入路径可独立验证 |
| 可播放 H.264 | 编码路径可独立验证 |
| HID 报告实验 | USB 控制路径可独立验证 |
| Socket 协议与服务接口说明 | 可替换或改造底层视频程序 |
| 冷启动与恢复记录 | 方案具备重复部署依据 |

这种组织方式允许读者先运行配套方案，再选择深入某一层；更换主板或模块时，也能判断哪些配置需要重新适配。Go 与前端的实现教学不在本指南范围，配套版本和接口仍需随交付记录固定。

## 当前指南的验证记录

当前正式程序已完成视频、USB HID 和服务拆分后的上机检查；12 Mbps 版本完成六轮固定序列编码、600 帧实际 WebRTC 接收与解码，以及视频进程重启恢复。具体条件见[性能测量](../encoding/video-performance.md)。**这组结果属于短时回归**，不能替代新版过夜与冷启动验收。

教学用采集与键盘示例通过编译检查，KVM2 接收器通过分段、长度与截断等协议测试。独立示例的实机取帧、直接报告发送、独立 HDMI 编码落盘，以及配套整包恢复仍需各自保存实际验证记录。**正式服务可用不等于这些教学步骤已经逐项执行**。

阅读完页面可标记学习完成；**该标记记录学习进度，不代表硬件已经通过本页验收**。实际验收报告应按上表保存自己的条件和结果。
